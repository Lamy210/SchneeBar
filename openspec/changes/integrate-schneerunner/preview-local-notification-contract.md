# D2 draft: preview-only legacy notification transport

Based on the fully combined integration HEAD 8973d273 and successful #396 CI. Existing Runner v1 observable contract: notification name identifies build/character, object is a JSON string. No Runner code copied. Apple documents main-thread delivery on modern macOS, possible queue loss and unbounded latency (https://developer.apple.com/documentation/foundation/distributednotificationcenter). This is unauthenticated advisory display only.

Preview opt-in defaults off, no persistence, production observer or GitHub capability. Active runtime session owns a distinct selector observer, revokes on stop/hide/sleep/conflict/disable, removes observer before replacement. Select deliverImmediately so menu-bar/background use is possible with AppKit suspension; never globally change suspension. No application-side per-message Task/backlog. Late callbacks from revoked observer carry obsolete UUID; v1 cannot identify delayed/replayed notifications delivered to a newly registered observer. OS delivery/copy costs and transport queue are not controlled by these application bounds.

Raw attempt admission and quarantine occur before lazy payload conversion. Check NSString UTF-16 length then bounded UTF-8 byte count before Data allocation. Reject non-string and oversized objects; no raw payload logging. Existing decoder/lane quotas remain. Runtime state/rate observer publishes deadline expiry even with CPU polling disabled; callback must not reenter runtime. Headless model tests exercise synthetic delivery, not actual distributed notifications. Add lazy-admission, UTF-8 bounds and lifecycle/expiry tests. Actual two-process delivery, background/sleep storms, power and memory, OS suspension behavior, permissions, sender authenticity limitations and ADR gates remain open. No main promotion or release.
