# C2b11 draft: durable owned pack selection

Stacked on #404. This is an API, not startup/UI wiring. The private root contains optional fixed .selection-v1 regular file with exact 40 bytes: v1 newline, canonical lowercase UUID, newline. Absence is built-in. No source path, bookmark, credential, event opt-in, speed, notification, or Runner settings stored. Require local private owned root, same-device, private UID/mode, single-link regular nofollow record. Unsafe record rejects read/reset; malformed private content requires explicit reset. Inventory ignores the safe fixed selection record for slot counting; unsafe record or any pending/unknown entry blocks install. No decoding in inventory.

Explicit select takes exclusive root flock, validates complete catalogue by UUID, then writes .selection-pending using exclusive create, fsync and a same-parent rename (no-replace if old absent). Keep old record on precommit failure, remove only newly created pending file on normal rollback. A crash before rename leaves pending uncommitted; never replay it, explicit discard validates the file type/ownership. Invalid existing contents can be replaced by explicit successful selection; built-in reset unlinks safe record. Restore takes exclusive lock, returns built-in for absence, fully reloads otherwise. If selected pack is missing or fails revalidation, clear old record and return unavailable(UUID) for UI fallback, never silently resurrect it after repair. Cancellation is not invalidity; no reset on cancellation. Unsafe preference/lock errors propagate; caller must show default and recover explicitly. Trash selected pack clears preference before rename; if rename then fails, default remains selected (caller must reconcile actual state). Restoring trash never selects it. Cooperating mutations serialized; current renderer not yet connected and cannot be assumed updated. No automatic start, UI, real app root creation or production linkage.

Atomic visibility is not power-loss durability. Same-UID noncooperating mutation, ACL, ancestor/mount changes, crash fault injection and real-device verification remain open. Four native regression fixtures cover selection and rejected choice, trash/restore and damaged pack, injected write failure and pending recovery, unsafe record and explicit reset. Broad task completion and main promotion remain gated.
