# E2a draft: bounded native completion history

Based on merged #439–#441. Extend pure FocusCore independently of storage and OS effects. Project only snapshots with a completed countdown phase; running, paused and cancelled countdown phases create no entry. A completed intermediate Pomodoro phase remains recordable even if the remaining session was cancelled. Count each completed focus/short-break/long-break phase separately. Record planned duration and authoritative deadline, not measured active time, observation time or an inferred start timestamp. No aggregate productivity metric or legacy history equivalence claimed.

Identity is countdown UUID for standalone countdowns and (session UUID, step) for Pomodoro phases, with countdown UUID preserved as metadata. Fresh source UUIDs are a caller obligation. Retained identical entries are idempotent; same retained identity with different metadata is rejected without mutation. Keep at most 500 entries (task 9.6's compatibility ceiling), ordered by descending deadline, ascending source UUID string, then ascending step (nil before numeric). Insertions outside that retention window are ignored. Identical replay of an evicted older entry cannot displace newer entries; there is no unbounded historical tombstone set and conflicting metadata for an evicted identity is not detectable. This is a bounded projection, not an exactly-once event ledger or a notification delivery log.

Version 1 Codable validates entry shape, deadline/duration bounds, phase parity and step bounds, standalone identity consistency, entry count and duplicate identity. Normalize ordering on decode, reject malformed/future records instead of silently dropping them. Future file adapter must also enforce byte limits before decoding. The pure model performs no file reads/writes, deletion of existing user data, migration, notification scheduling or shipping UI change. Store completion plus history atomically or use a recoverable journal before allowing the current slot/phase to advance; separate independent writes could lose history after a crash. Imported data remains notification-inactive. No source code or artwork copied from Runner.

Five new tests cover completed-only projection and original deadline, per-phase Pomodoro restoration/replay, conflicting retained identities, 500-entry retention and deterministic ties, version/duplicates/oversize/entry shape. Linux Swift 6.2.1 SwiftPM harness ran five new and five existing Pomodoro tests successfully. Deliberately removing retention resulted in three failures in the retention test; restored implementation passed all ten. Source and test Git blob hashes match the local harness. Native CI still required. Task 4.2/9.6 remain partial; durable history, recurrence, snooze, notification and UI are separate. Real-device validation, rights, ADR approval and main promotion unchanged.
