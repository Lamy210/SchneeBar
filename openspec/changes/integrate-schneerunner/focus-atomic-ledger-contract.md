# E2b draft: atomic native focus state and history

Depends on #442. Preserve individual countdown and Pomodoro stores and their wire formats while extracting their synchronous pure transitions. Add a new FocusLedgerStore with a distinct caller-supplied private file, one actor instance per file. Version 1 snapshot holds optional native countdown and Pomodoro slots and bounded FocusHistory. No automatic conversion of old files, migration, production composition or notification dispatch. Future production host must choose this ledger as the only writer of native state, never use independent per-slot stores alongside it for the same sessions.

Each command reads the committed snapshot, checks current identities using existing transitions and updates the corresponding slot. A new completion projects the completed state into history in the same transaction; only after atomic replacement does the owner receive a completion. No suspension during read/modify/write and no second history write. Reuse of a retained identity within its namespace is rejected; caller must generate fresh UUIDs, including after eviction. No-op commands avoid writes. Decode validates current-slot/history coherence: a completed slot must have a matching retained entry or be legitimately outside retention; incomplete slots cannot have a matching completed entry; future steps of the current Pomodoro are rejected. This is not a proof of integrity for all prior history or a detection mechanism for all external tampering. Reuse the bounded regular-file reader, limit snapshot to 256 KiB, retain at most 500 history entries. Reject invalid records without repair. The existing private-parent and single-writer assumptions remain.

Precommit write failure preserves old snapshot; unknown commit outcomes require reload. Atomic replacement is not fsync/power-loss durability or cross-process locking. A crash after commit but before OS notification dispatch can still omit delivery. No outbox, notification receipt, measured activity duration, legacy import, UI or production dependency here. Tasks 4.1/4.2/9.6 remain partial; explicit migration, reminders, notification scheduling, real-device verification, rights and ADR/main gates remain.

Four new tests cover both slots and history restoration, failed write/retry, 16 concurrent requests across both slots producing exactly two events, and missing retained history rejection. Linux Swift 6.2.1 SwiftPM harness ran 24 tests (4 new, 10 existing persistence, 5 Pomodoro and 5 history), with existing bounded reader Darwin-to-Glibc adaptation only in the harness. Omitting countdown history projection caused all four new tests to fail with six issues; restored source passes all 24. The four changed source/test blobs match the harness. Native Xcode/Tuist CI must independently pass before merging.
