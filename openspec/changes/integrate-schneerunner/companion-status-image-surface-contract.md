# C3g draft: borrowed status-button image surface

Independent slice based on #410 integration. The main-actor adapter accepts an existing NSButton (including the host NSStatusBarButton) only after the composition owner has established exclusive image ownership. It creates no NSStatusItem, changes only image, and holds a weak reference to the host. Begin captures the existing image including nil; clear restores it and keeps session; end/stop restores and invalidates the current session. Prior session callbacks must not mutate the new surface. Capture the value returned by the image getter after assignment for identity comparison.

If the image is replaced by a different object or the button disappears, relinquish without overwriting the external writer. This is a defensive identity check, not a lock: in-place mutation or replacement by the same object is outside detection. Explicit owner stop before surface teardown is required; deinit does not promise AppKit restoration. Only the owner may acquire a new session. The future host must bind renderer callbacks to the same session, stop renderer and revoke on loss of approval/ownership/sleep, preserve original button target/action, text, tooltip, image position and accessibility label, and use the existing app-owned CPU sampler/scheduler. No production or preview wiring in this slice.

Four regression functions use standalone NSButton and procedural NSImage to test preservation, restoration, stale sessions, external replacement and weak ownership. They do not allocate an NSStatusItem or exercise the actual menu bar. Native CI, real Mac image identity, ownership/lifecycle smoke tests, ADR/artwork rights and release gates remain pending.
