# C3k draft: single lifetime companion host composition

Based on merged #415/#416. The existing host must explicitly grant exclusive access to its existing image slot before constructing one CompanionHostComposition. It owns the settings editor, preference bridge, bounded owned-pack acquisition, renderer and one-shot shared CPU refresh. The composition creates no status item, sampler, independent timing loop, transport or filesystem mutation. All committed preference transitions pass through acquisition, and demand notifications report CPU and local event session changes to the host. The caller serializes both CPU demands in its existing scheduler and invalidates CPU before replacing its configuration generation; notification callbacks must not synchronously reenter the owner.

Explicit ownership withdrawal, detected external image replacement or a vanished button ends the lifetime. Detection occurs before a request, environment/settings refresh, CPU host iteration (including frozen/no demand) or a frame/clear. Frame-side loss reports on the next main actor turn to avoid reentry into runtime reconciliation. Terminal stop cancels acquisition, revokes runtime, invalidates CPU, restores original image only while still owned, and emits zero demand. Sleep/release denial/hide clear the catalogue without terminal ownership release if ownership persists. Retain the stopped owner until its non-cooperative worker drains before constructing a successor; no implicit reacquisition, process-wide worker lock, or immediate decoder cancellation.

Two asynchronous tests cover committed settings, shared CPU adapter, sleep/wake, terminal stop and frozen external image loss with procedural catalogue and standalone NSButton. This is a reusable composition root for later MenuBarController wiring, not production/preview wiring. The actual host-owned demand reconciliation, acquisition of built-in or restored selection, event transport, real Mac status item and release approval remain necessary. No original acceptance gate closed.
