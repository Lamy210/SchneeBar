# C2b5 draft: aggregate budget and animated pack decoding

Stacked on #398 at 024906fa. Independently authored behavior based on Runner v1 GIFAnimationLoader/AnimatedImageLoader: GIF/APNG/WebP match actual content type and require at least two frames. Other three recognized kinds (procedural singleImage, spriteSheet4x2, pngSequence) fail closed before any clip is read until implemented. No promise of complete v1 compatibility.

Read manifest through the descriptor reader, then read each referenced file once with remaining aggregate encoded-byte limit 32 MiB (plus 64 KiB manifest separately). Count repeated paths per declaration; no shared clip deduplication. Retain ImageIO sources from the exact captured bytes, preflight every frame's dimensions/count/timing and aggregate 240 frames, 16M metadata pixels, before any explicit frame decode. Each clip retains existing 120-frame/4096-dimension bounds. Decode sequentially with remaining actual pixel budget checked before bitmap normalization, return only a complete validated catalog; no partial result, output file, owned storage or metadata persistence. Clamp timing as existing decoder does. Single-file decoder public API remains unchanged. Internal test limits may only tighten production ceilings.

Selected security scope balanced around synchronous load. Call off main; do not expose pack picker until single-worker queue and generation fencing have been reviewed. ImageIO source inspection can allocate/decode internally, and explicit frame acquisition may allocate before actual dimensions are known; this is an application admission/retention bound, not a hard RSS ceiling. Source mutation between reads may yield a mixed capture; the selected root descriptor is not an immutable snapshot. No archive extraction, copy/staging, format conversion, production wiring or release.

Independent synthetic GIF and Pillow-generated 4x2 two-frame APNG/WebP (100/200ms) fixtures, metadata 16 pixels per clip. Verify format, timing, fallback, exact aggregate limits and over-limit rejection under small injected budgets, unsupported kinds and later invalid data. Native ImageIO/macOS CI is pending, especially animated WebP/APNG status/compositing; fixture generation verifies encoded frame count, not native compatibility. Keep rights, actual memory measurements, staging and real-device gates open.
