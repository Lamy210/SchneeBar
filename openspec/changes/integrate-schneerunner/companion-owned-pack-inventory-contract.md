# C2b9 draft: owned inventory, UUID reload and admission quota

Stacked on #402. Existing application-controlled private local root only; do not use the original Runner store. List at most 128 raw root entries including dot/hidden entries via fdopendir/readdir on separate openat directory descriptor. Only lowercase canonical UUID.schneerunner names identify committed slots. Count canonical stage remnants and unknown names separately, never follow or remove them. Count invalid committed slots toward quota too. List bounded manifest metadata only, invalid directory/manifest maps to name=nil, not automatic repair. A valid manifest is not full decode integrity. Sort by UUID. Selection accepts UUID, opens child directory via root fd/no-follow and checks same device/private uid/mode, then revalidates all clips through that pinned descriptor. No source URL persisted or returned.

Maximum 16 committed slots; reserve 16 * (32 MiB + 64 KiB) = 513 MiB logical encoded/manifest allowance for correctly installed, unmodified packages. Not actual filesystem allocation, not a verified size bound on externally altered contents, not a hard process RSS limit. Deny install if any canonical stage or unknown entry is present, or slot count at limit, before reading source. Count cap 128 rejects excessive entries; no partial scan. All cooperating install/list/load operations use nonblocking shared/exclusive flock on root directory fd held until close; fail closed on error, no persistent lock file. Validate macOS local filesystem support and contention; this is advisory coordination, not protection against noncooperating same-UID writes/ACLs or malicious ancestor/mount changes. No deletion/recovery mutation, filesystem free-space estimation, duplicate merging, selection preference, UI, or production linkage. Explicit later recovery proposal must safely handle leftovers and unknown entries without deleting unrelated data.

Four added native fixtures: metadata and UUID reload, damaged manifest/symlink refusal, quota and stage/unknown preservation, scan limit and lock contention. Existing three store tests remain. Latest macOS CI required, especially flock semantics. Do not mark broad OpenSpec tasks complete or distribute.
