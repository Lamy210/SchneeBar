# C3c draft: shipping host activation policy (no production connection)

Baseline integration ebb35532 after #408 and main workflow sync. ADR-0004 remains Proposed. The pure CompanionCore configuration and policy have no GitHub, AppKit, notification, storage or scheduler dependency. User preference enablement defaults false, local events defaults false. Separate explicit release approval and menu surface ownership are runtime inputs, not persisted, not derived from a preset or event. Production composition must leave approval false until recorded acceptance. Minimal hides character, Dashboard and Companion permit the independently opted-in surface; all presets leave permissions and enablement unchanged. No Focus scheduling policy is affected. Codable preference model is not connected to a store; unknown/malformed format must fail closed at the future storage boundary, no fallback to enabled state.

Availability priority: release block, disabled, hidden, asleep, surface unavailable, awaiting catalogue, active. Only awaiting catalogue and active admit explicit asset work; hide/disable/sleep/ownership loss/release revocation revoke asset session. A host must additionally cancel/fence individual latest requests (same-session replacement handled by existing import queue), discard inactive catalogues when required, and revalidate on re-entry. Manual speed and Reduce Motion/freeze suppress automatic CPU demand; local events require active catalogue and explicit opt-in; reduced motion does not grant new permissions. No UI-side timer. Existing shared HostCPUSampler still sole owner. This policy does not create a renderer or status item.

Next host adapter: use existing MenuBarController button image only, never alter target/action, title, tooltip, accessibility status, popover or existing widget ordering. Restore original snowflake on revoke. Serialize host configuration with existing configurationTask/revision; one shared sampler with both widget and companion leases, sample at same monotonic deadline, no second polling loop, stale callbacks rejected. On unavailable button, failed asset or sleep revoke lease and restore existing presentation. Existing developer preview remains independent. Explicitly verify real Mac single-owner, no disabled work, memory/CPU/wakeups, visual/accessibility and rights/ADR before actual app dependency or main promotion.

Four pure regression tests cover release gate/default opt-in, settings roundtrip and presentation presets, lifecycle asset fence, reduction/manual speed/event independence. No task completion or production activation claimed.
