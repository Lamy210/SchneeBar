# E1d draft: native Pomodoro persistence

Stacked on #439 and #440, not independently mergeable until both are integrated. Use the existing FocusPersistence target and bounded reader, with a separate caller-owned private file for one native Pomodoro slot. A single actor owns read/validate/mutate/atomic replacement without suspension. The caller must choose distinct countdown/Pomodoro/source paths, create the private directory, use one owner per file and never reuse session UUIDs. No cross-owner lock, revision CAS, OS notification or history. Keep countdown implementation unchanged; defer shared storage extraction until both record contracts are integrated.

A start rejects an unfinished session, including a completed intermediate phase waiting for advance, and rejects current ID reuse. Every other command, including reconcile, requires both the current session UUID and step. Reconcile after sleep completes only the current phase; advance creates a new deadline from the supplied time. No-op commands do not write. Return the result only after successful atomic replacement. Missing file is empty; malformed/future/over-limit/linked record fails without replacement. 4096-byte bound, final-component nofollow/nonblocking regular-file + link-count validation, trusted private parent directory. A failure before commit preserves the record; unknown commit outcome requires reload. Atomic replacement is not proof of power-loss durability. Completion is not a notification receipt and a crash after commit may omit delivery. Imported notification-bearing schedules stay inactive.

Five new tests exercise restart while awaiting next phase, stale reconciliation after advance, 16 concurrent completion requests, injected write failures on completion and advance, paused restoration and stale session commands, and preservation of invalid/future/oversized/linked records. Local Linux Swift 6.2.1 SwiftPM harness ran all ten persistence tests (five existing + five new) successfully, using the existing reader with only Darwin-to-Glibc adaptation outside the repository. Removing the step guard intentionally caused three failures in the stale-observation test; restoring the source passed all ten. Actual macOS CI remains required. Tasks 4.1/9.6 remain partial; no production wiring, history, scheduling, migration, real-device signoff, rights/ADR or main promotion.
