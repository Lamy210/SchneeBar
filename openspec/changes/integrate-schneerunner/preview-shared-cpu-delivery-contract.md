# C3n draft: preview shared CPU delivery

Based on merged #419. The existing, non-distributed Companion Preview now consumes HostCPURefreshPlan for wake deadlines and per-consumer refresh decisions. Each new configuration generation performs one initial refresh of the enabled consumers, even if the sampler cache was previously consumed. Subsequent iterations refresh only due or pending consumers. Recheck the plan after the widget refresh, since it can create a fresh observation for the companion. Retain the existing revision/cancellation checks before presentation. Cancellation is not reported as a counter failure. No extra timer or hardware counter source is introduced.

Two deterministic preview-model regressions cover both consumers sharing one bootstrap, cached deadline after a visibility change, zero demand and shared cached failure without an immediate retry. Existing tests cover restart, headless/no surface, conflicts, and generation changes. These are headless model fixtures, not measured real-Mac acceptance. No shipping target dependency, distribution, new permissions, copied artwork, or release approval. The preview remains separately launched and preserves current conflict detection.
