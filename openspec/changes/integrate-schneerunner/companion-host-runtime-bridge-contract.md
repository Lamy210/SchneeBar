# C3f draft: host preference-to-runtime bridge

Base #410, integration/schneerunner. The isolated CompanionFeature bridge reads committed storage on explicit refresh and platform/asset transitions, never an editor draft. Invalid or unsupported storage defaults to disabled. Release approval and ownership are host inputs defaulting false; no settings value grants them. No production or preview composition, new status item, independent CPU loop, filesystem work, transport registration or GitHub operation is introduced.

HostPolicy decisions are applied to the existing coordinator as one configuration before reconciliation, so an intermediate setting cannot enable animation, CPU or events. Only an active catalogue can render; manual/reduced-motion modes suppress automatic CPU demand. Catalogue replacement invalidates CPU requests and revokes the previous local-event session. Disable, hide, sleep, ownership loss or release revocation clear retained catalogue and pending publication, requiring a new validated catalogue on re-entry. The bridge issues one newest publication ticket per allowed session; obsolete, duplicate and revoked results are rejected. A current failed result clears the catalogue. Existing imagery remains until the current replacement result arrives.

The owner must exclusively drive the coordinator through this bridge for the governed inputs and call refresh after committed settings changes. It must also cancel/fence and bound actual asset acquisition, apply shared scheduler lease transitions, route local-event session changes, and explicitly stop before release of the surface. No observation of out-of-process writes, cross-process atomicity, or physical cancellation guarantee. Callbacks must not synchronously reenter as in the coordinator contract. Tests use procedural fixtures only. Native CI, actual composition, single-owner device checks, accessibility, ADR/rights approval and main promotion are still pending.
