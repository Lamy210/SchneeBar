# C3i draft: shared CPU refresh adapter

Based on merged #412 bc8724a6. The isolated feature accepts the host-owned HostCPUSampler and invokes sample(for: .companion) at most once concurrently per adapter generation, with no new loop, sampler, lease or timer. The existing host loop must reconcile combined widget/companion demand atomically before calling refresh, and compute its wake delay from the sampler; a companion refresh may consume a widget's cached sample. The runtime already rejects repeated sample identity/order. The owner checks current host configuration/lifecycle before and after suspension and calls invalidate before replacing a generation or lease; an obsolete callback cannot publish, even if acquisition continues. A current non-cancellation error clears reaction, while a cancellation does not masquerade as a sensor failure. Demand revocation and sleep must separately stop the runtime and reconcile sampler demand.

Three deterministic model/adapter tests cover inactive/manual/reduced motion, failure versus cancellation, and generation/invalidation at suspension boundaries. They do not prove physical sampler coalescing or actual host loop integration. Existing sampler tests remain authoritative for coalescing; real Mac performance and production owner wiring remain pending. The new dependency is only CompanionFeature -> SystemProvider, not App -> CompanionFeature. No change to approval, rights, distribution or original task completion.
