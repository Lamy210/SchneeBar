# E3b draft: persisted reminder intent and occurrence claim

Based on merged #444. Extend FocusReminderSchedule with structural validation for decoded occurrence cursors (valid UUID association, bounded finite date, valid Gregorian civil day or exact one-shot timestamp). No per-reminder time zone. Add FocusReminderState v1 with immutable schedule/origin, disabled-by-default intent, last observed occurrence and optional pending ticket UUID. Imported-origin items reject activation, have no pending occurrence or consumed cursor, and invalid persisted imported-active records fail closed. This is an app-owned data contract, not a defense against arbitrary same-user file editing or a substitute for verified migration origin mapping.

Replan with the owner-supplied current calendar/time; a changed occurrence replaces the ticket, identical future intent retains it, disabling clears it while retaining the cursor. Claim requires matching current ticket, due date and current recurrence under supplied calendar; a stale/early claim fails without mutation. A successful claim advances the cursor and clears the ticket. A claim is consumption, not evidence of OS delivery. Replan is strictly future and skips missed deadlines; the future scheduler must decide explicitly whether to claim a due persisted ticket before replanning. No automatic missed-occurrence backfill or side effects.

One FocusReminderStore actor per caller-supplied existing private file, 16 KiB bounded record, existing bounded regular-file reader and atomic replacement. Create rejects existing records, mutation requires current schedule UUID, read/modify/write has no suspension, publish claimed occurrence only after save. No concurrent owners or cross-process lock; unknown commit outcome requires reload. No automatic reset/repair. Foundation atomic replacement is not fsync/power-loss durability. Origin classification and distinct paths are caller responsibilities. No multiple-reminder inventory, edit/delete/revision, labels, snooze, notification request registration, outbox or OS permission handling. A crash after claim commit and before delivery may omit a notification. Existing data-only migration and production gates remain in force.

Five added tests (one malformed cursor, four store tests): durable claim + travel rollback, early/context-changed/revoked tickets, imported activation/corrupt record, failed write + 16 concurrent claims. Linux Swift 6.2.1 isolated SwiftPM harness ran 11/11 including six existing recurrence tests; the harness uses a local bounded POSIX reader stand-in, not the exact Darwin production implementation. All five changed source/test blobs match the local harness. Mutating claim to omit ticket clearing failed the selected concurrency/restart test with invalidRecord; restoring the source passed all 11. Native Tuist/Xcode CI required independently. Tasks 4.2/4.3/7.3/7.5/9.6 remain partial; production host, migration, snooze, notification and real-device/security/rights/ADR/main gates unchanged.
