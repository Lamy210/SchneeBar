# C4a draft: explicitly confirmed irreversible library recovery

Based on merged #431 and #432. Extend the existing single exclusive worker for three explicit actions: permanently purge a trashed pack, discard an abandoned import stage, discard an uncommitted selection record. A current inventory and admitted asset session are required. The settings editor binds one-use confirmation to the action, UUID where applicable, current session and inventory; exact DELETE text is required for irreversible actions and cleared whenever the confirmation changes. The low-level host action API is trusted and does not itself present a dialog; callers must arrange explicit confirmation. No automatic purge, repair or replay.

PurgeUnselectedTrash protects the saved selection in the same exclusive root lock as deletion, refusing matching or malformed selection records. The acquisition layer rejects purge of an admitted displayed pack. Existing bounded preflight/identity checks, no-follow and canonical layout constraints apply. Keep legacy preview recovery semantics unchanged. Stage removal is restricted to the reported stage UUID. Discard pending selection removes only the fixed pending record; leave the last committed choice unchanged. This is not a compare-and-swap against external process inventory snapshots; lock/identity checks apply to the currently observed record. Unknown entries are counted, never cleaned automatically. Re-read inventory after every operation; source paths and unrelated data are not exposed or cleaned. Cancellation fences late UI publication, not already committed deletion; partial cleanup may remain and requires explicit observation before retry.

Two new regression fixtures exercise protected dangling/malformed selection on purge and actual host recovery with typed confirmation, stale/repeated tokens, abandoned stage/pending record/trashed pack removal, committed choice and unknown file preservation. Native CI, actual Mac UX/accessibility, production owner integration, real Mac resource metrics, artwork rights and ADR/main promotion remain pending. No shipping dependency or release changes.
