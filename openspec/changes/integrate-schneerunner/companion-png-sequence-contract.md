# C2b7 draft: PNG sequence pack decoding

Stacked on #400. Runner v1 sequence observable behavior: visible entries all PNG regular files, at least two, numeric case-insensitive en_US_POSIX ordering, identical dimensions, 12fps. Preserve those semantics; deterministic UTF8-byte tie-break when comparison equal. Use descriptor-relative enumeration (fdopendir/readdir) on the opened manifest path, no URL path reacquisition. Maximum 256 raw directory entries including hidden/dot entries per sequence, up to 120 visible frames and remaining pack frame budget. Hidden entries are ignored and never read. UTF-8 names and full relative path must fit existing limits. Read each visible leaf through same pinned directory descriptor, reject links/hardlinks/nonregular/device changes. Directory mtime/ctime rechecked after reads; not a complete immutable snapshot or defense against concurrent relocation of an open directory. Bounds intentionally stricter than Runner.

All visible PNGs must have actual PNG single-frame content, same dimensions, and fit remaining cumulative bytes, frames and metadata pixels. Reuse exact prepared sources for sequential actual decode with remaining pixel budget and dimension recheck; return a single 12fps clip. No partial catalogue or persistence. The six known clip kinds now have an implementation path, not verified full parity (procedural motion differs; stricter limits; platform image decode/composition unverified). Four regression fixtures: numeric ordering, equal dimensions and budget, visible wrong extension/symlink, hidden-entry scan cap. Existing missing-sequence fixture updated to expected descriptor failure. Native macOS tests, file mutation, accessibility and memory acceptance remain pending. No new app dependency or release.
