# C3o draft: host-owned local event ingress

Based on merged #419. CompanionHostComposition exposes a synchronous, lazy event entry point. The current image slot, live owner and both published and runtime session must match before the payload closure is evaluated. Existing CompanionLocalEventIngress remains responsible for admission windows, UTF-8 size, parser, expiry and quarantine. Loss of ownership ends the host lifetime without overwriting the external image.

Move the existing explicitly started/stopped macOS distributed-notification subscriber from Preview into CompanionEvents, preserving its immutable session, two allowlisted names, main-thread delivery, bounded lazy conversion and no per-notification Task. Preview calls the same code via its existing typealias. A future approved host can construct one subscriber per published session, capture the composition weakly, forward through the new entry point, and stop/remove the old observer before replacing it. No automatic subscription from the composition, no shipping app dependency, no sender authentication or privileged action. The transport's object may already have been allocated by the OS; the 4096-byte ceiling applies to application parsing.

Two host fixtures cover committed opt-in, stale session across suspend/resume, disabled event reception, oversized payload and lost image ownership without payload evaluation. Existing preview tests exercise opt-in and payload bounds; actual Mac notification delivery, no-GitHub-write integration evidence, rights and ADR approval remain pending. No task completion or production activation claimed.
