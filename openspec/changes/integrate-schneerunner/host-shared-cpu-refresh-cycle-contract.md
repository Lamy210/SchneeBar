# C4c draft: common host CPU refresh iteration

Based on merged #433, independent of #434. Extract the existing widget/preview CPU delivery phase into HostCPURefreshCycle in the existing SystemProvider target. No new target, sampler, worker, lease owner, timer or production CompanionFeature dependency. MenuBarController calls with companion false, preserving the shipping feature gate and non-CPU widget scheduling; preview calls with its existing two demand flags and first-iteration force. Configuration reconciliation, deadline calculation, sleep/wake and loop ownership remain with callers.

A disabled consumer incurs no plan acquisition or refresh callback. A forced refresh still requires a live consumer lease. Read the shared plan immediately before each enabled consumer; re-read after widget acquisition to deliver the same cached success/failure to companion rather than wait a full acquisition window. Check cancellation and host generation before and after asynchronous plan/refresh calls; false means skip subsequent processing in the obsolete iteration. Consumer callbacks still fence publication themselves. This does not change sampler cache acknowledgement semantics, measurement intervals or grant new permissions.

Three deterministic regression fixtures cover cached delivery after widget acquisition, generation invalidation across asynchronous phases, and disabled/revoked/just-delivered consumers including force. Existing preview/shared-sampler regressions and full app CI still required. Native Mac acceptance, artwork rights, ADR approval, CompanionFeature shipping dependency, and main promotion remain pending.
