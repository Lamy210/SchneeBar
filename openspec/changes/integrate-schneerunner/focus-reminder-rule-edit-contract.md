# E3d draft: atomic replacement of native reminder rules

Based on merged #446. Add replaceRule on the existing collection actor. Only native entries may change their scheduling rule. Validate and canonicalize the requested rule first; identical canonical rules are a no-op preserving the identity, cursor, ticket, and bytes. Imported entries reject rule edits as well as activation. Keep the original title and enabled intent. Changed native rules are explicitly new schedule identities: generate a fresh UUID, drop the old cursor and ticket, and if enabled compute the next strictly future candidate with the supplied current calendar/time. A consumed one-shot may therefore be explicitly rescheduled; a recurring edit may create a new occurrence on an already observed civil day. This is a proposed product behavior requiring UI explanation/confirmation, not a silent replay of the unchanged rule.

Replace one entry and persist the entire collection once; capacity does not increase. Validation, recurrence errors and precommit write failure leave the old record intact. On successful commit old UUID and old ticket can no longer act on the replacement, including queued rule edits. The caller must adopt the returned ID and refresh its snapshot; UI identity is not stable across rule edits. No automatic cross-process locking, notification cancellation, migration, activation of imported data or snooze. Old OS requests still require reconciliation against the new snapshot. A consumed event already handed to a delivery adapter cannot be recalled by this transaction. Uncertain write outcomes require reload. Existing 64-entry/256 KiB limits and version 1 wire format unchanged.

Four regressions exercise changed-rule identity and ticket revocation after restart, unchanged canonical weekday ordering and byte preservation, disabled intent plus imported/invalid rules, and write-failure preservation and successful old-ticket claim. Linux Swift 6.2.1 isolated SwiftPM run passed all four new tests; collection implementation, recurrence/state and new test blobs match repository exactly. The harness substitutes a basic file reader and only the individual store Command type; this does not validate production Darwin file safety or the full target suite. Mutation constructing the replacement with the old ID failed the selected regression with duplicateIdentity; restoring the original source passes 4/4. Native CI required before merging. No new production dependency, notification, migration, or release-gate change.
