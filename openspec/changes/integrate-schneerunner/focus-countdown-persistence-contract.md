# E1b draft: single-owner native countdown persistence

Based on merged #438. Keep FocusCore pure. Add a separate FocusPersistence target using the existing bounded regular-file reader in SchneeBarCore. One native countdown slot in one caller-supplied existing app-private directory, never a Runner path. The owner must supply an exclusive actor instance per file, unique fresh countdown UUIDs, and serialized/current UI commands. No cross-instance/process lock, revision-based command CAS, history, migration or production dependency. Replacing a terminal slot discards only that slot; history is a separate later requirement. No generated path from untrusted input or automatic directory creation/deletion.

Every command reads the committed v1 FocusCountdown record and validates before writing. Missing file is empty. Invalid/future/oversize data and unsafe file types fail closed, without reset. The payload limit is 4096 bytes. Reuse the existing final-component nofollow/nonblocking regular file and link-count checks; the directory is a trusted private boundary, not protected against noncooperating same-user external mutations. Explicit start rejects active state (including elapsed-but-unreconciled running state) and current ID reuse. Other commands require current UUID. No-op commands avoid writes. Atomic Foundation replacement precedes publication of result/completion; no await inside the read/modify/write transaction. Sequentially restarting the owner preserves phase/deadline; simultaneous calls on the same owner cannot both produce a completion. No notification dispatch here.

Atomic replacement is not an fsync/power-loss durability guarantee. A failed precommit write preserves the previous record and allows retry. If an I/O error leaves commit outcome uncertain, reload the record before reporting state; do not replay an uncertain notification. A crash after committing completion but before consuming the returned event can omit a notification. Stable notification reconciliation and history/outbox design follow separately. Manual backward clock behavior remains as documented in E1a. Imported notification schedules stay inactive.

Five focused tests verify real file restart/completion, concurrent 16-command completion, injected precommit write failure/retry, stale/current duplicate ID protection and paused restoration, malformed/future/oversize/link preservation. Local Swift 6.2.1 Linux SwiftPM harness verified five tests with the actual new source/test and existing FocusCore, adapting only the existing reader's Darwin import/namespace to Glibc for the harness. Mutation: skip the completion write, producing two failed assertions in restart test; restore production source and all five pass. No mutation/harness changes in repo. Native Xcode/Tuist CI required independently. Tasks 4.1/9.6 remain partially implemented; Pomodoro, history, scheduling, migration, actual host wiring, real-device/rights/ADR/main acceptance pending.
