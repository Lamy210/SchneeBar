# E3a draft: floating-local reminder recurrence

Based on merged #442/#443. Independently implement pure native recurrence from the existing productivity spec. No Runner code copied, no OS notification scheduling, persistence, migration or production UI. Rule v1 supports an absolute one-shot timestamp, daily local hour/minute, and selected Foundation Calendar weekdays (1–7, Sunday = 1 for Gregorian). Validate hour/minute, unique nonempty weekday set, finite bounded dates and version; sort weekdays for deterministic representation. Owner supplies current system calendar/time zone per calculation; do not persist a per-reminder zone.

Calculate strictly future occurrences, one candidate per local day, using Calendar.nextDate matchingPolicy nextTime and repeatedTimePolicy first from the beginning of that day. Reject a candidate on a different day; never choose the second repeated hour when now is after the first. Weekday selection uses the supplied calendar. One-shot timestamp remains absolute across zones. No missed-occurrence backfill. Check a bounded 16-day search and report searchLimit rather than looping indefinitely. Extreme calendar/date behaviors beyond tested Gregorian cases remain unverified.

Use a reminder UUID plus Gregorian civil date in the supplied time zone as recurring occurrence identity, without persisting a zone; one-shot identity uses UUID and absolute date. Optional lastObserved occurrence is a conservative monotone civil-date high-water mark: skip that day and earlier days even after travel or manual clock rollback, including long rollback by jumping near the cursor. This can suppress an unobserved earlier day after travel; deliberate proposal prioritizing duplicate avoidance. Owner must supply only a genuinely observed/committed occurrence of the same current schedule; use fresh UUID for a changed rule until revision semantics exist. Occurrence cursor is in-memory, not a durable receipt. No claim of restart deduplication, notification delivery or full parity across non-Gregorian calendars. Imported notification-bearing data stays inactive per existing spec; recurrence calculation never grants permission.

Six tests cover New York spring gap (02:30 resolves to 03:00), autumn first repeated hour and skipping second, selected Tokyo weekdays, Tokyo/New York travel and long rollback with an observed cursor, one-shot absolute date/replay, malformed rules and version. Linux Swift 6.2.1 SwiftPM isolated test 6/6 after fixing explicit try inside Swift Testing require. Changing repeatedTimePolicy first to last caused three assertion failures in the autumn test; restored source passes all six. Both new blobs match local harness. Native macOS tests required before merge. Rights, ADR and main promotion gates unchanged.
