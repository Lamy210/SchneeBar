# C3e draft: isolated host preference editor

Depends on #410. New CompanionFeature model and SwiftUI form are not connected to the shipping app or preview target. Settings edit only local intent, never release approval, ownership, catalogue, runtime, CPU, notifications, or authentication. Initial load and draft edits make no writes; explicit Save and read-back are required. Reload or Discard replaces unsaved edits; no persistence occurs for unchanged settings. A detected change to the stored record identity or decoded status/value cancels Save or Reset, reloads current values and requires a new user action.

Unreadable/future-version records disable ordinary editing and saving. A separate destructive confirmation with a one-use token allows scoped reset only when recovery is required. Cancel, reload and stale tokens cannot reset. Read and identity are captured from one UserDefaults lookup. Data is compared byte-for-byte (including ignored fields, malformed bytes and future-version payloads); non-Data property-list values are compared by binary serialization (may conservatively reject equivalent values). Unavailable identity refuses Save/Reset. Identity stays in memory; it is not logged or displayed. Comparisons are not atomic cross-process CAS and do not detect ABA changes or guarantee detection of concurrent non-cooperative writes. Intended one main-actor owner only; no cross-process consistency or durable disk acknowledgement. Explicit reset removes only the preference key; not artwork, library, or other settings.

Six model tests cover draft/discard/save, external valid value change, canceled/stale reset, recovery status change, same-category malformed/future/wrong-type replacement, and equal-intent changed Data. Native CI, UI hosting, keyboard/VoiceOver, Japanese localization, confirmation interaction, unsaved navigation UX and actual app composition remain pending. No original OpenSpec task closed; no production activation, distribution, or approval change.
