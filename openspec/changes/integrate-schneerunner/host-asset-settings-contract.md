# C3t draft: developer host asset settings

Based on merged #424 and #425. Provide an optional owner-bound section of the existing settings form. The original preferences-only initializer remains unchanged. The section accepts an explicitly entered installed UUID (metadata picker remains a later slice), separates display-only from durable save, exposes restore and explicit confirmed deselection, and reports visible status. Editing a UUID or preference draft must not write. Only committed preferences and the existing runtime gate allow asset operations. All actions require an idle worker; invalid UUID, unavailable host and failed admission are rejected. A one-use deselection confirmation is invalidated on session, status, availability or busy changes.

The queue notifies the owner when the actual worker slot drains, including a cancelled non-cooperative operation without a result callback. The owner synchronizes the observable editor on admission, lifecycle, adoption and drain; no new polling task or file I/O from the UI. Clearing changes the owned selection record only, not pack contents. No automatic restoration or repair. Selection cancellation is not disk rollback; restore after drain if the outcome is unclear.

Two deterministic host/editor fixtures cover draft/UUID validation, disabled and busy state, one-use stale confirmation and drain notification after cancellation. Native CI and real Mac accessibility/keyboard/dialog and localizations remain to be verified. No shipping app dependency or UI hookup in MenuBarController, new artwork, release approval, distribution, or main promotion.
