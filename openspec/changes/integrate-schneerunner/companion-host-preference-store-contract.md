# C3d draft: versioned host preference storage (no production connection)

Baseline: #409 squash d87af666, integration/schneerunner. ADR-0004 remains Proposed. No shipping app dependency, Settings UI, renderer, CPU lease, notification listener, Runner migration or GitHub connection is added.

The CompanionFeature adapter owns one explicit injected UserDefaults domain and the single namespaced key SchneeBar.companion.hostPreferences. A v1 UTF-8 JSON Data record has version and all CompanionHostPreferences fields, with a provisional 4096-byte read/write bound. Missing, valid, invalid, and unsupported version are distinct outcomes. Missing/invalid/unsupported all expose default disabled intent, no local events. No registration, automatic repair, migration, startup write, or fallback to enabled. A future version is reported before decoding the payload. Unknown additive fields within v1 are ignored; release approval, menu ownership, asset session and catalogue revision are not persisted or derived from storage.

Only explicit user-intent save updates a valid/missing record. Invalid or unsupported data is preserved and normal saves are refused; a separately confirmed reset may remove only this key. UI must surface recovery without silent reset. The main-actor store serializes the intended single owner; it does not promise cross-process exclusion, crash durability, protection against other same-user writes or synchronous disk flush. The composition root must supply its own domain without registered fallback values and leave release approval false pending the existing approval gates.

Four regression tests use fresh random isolated suites, covering missing/default, roundtrip/reset scope, malformed/wrong-type/oversize/invalid enum, future version preservation, and injected approval fields not granting runtime permission. macOS CI, actual Settings binding, signed-app persistence, restart and explicit recovery UX remain to be verified. No original OpenSpec task is closed by this slice.
