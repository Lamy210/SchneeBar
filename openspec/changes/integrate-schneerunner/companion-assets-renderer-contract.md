# Companion asset and menu renderer slice C2a/C3a

Status: independent implementation draft only. ADR-0004, reuse rights, app wiring and real-device acceptance are still gates. No Runner artwork, source or tests copied. Synthetic CoreGraphics fixtures only.

## Asset admission

The decoder accepts only existing in-memory Data, not arbitrary URL, archive, network or filesystem. Reject empty payload or >32 MiB before ImageIO. Identify content from ImageIO UTI, allow PNG (including APNG), GIF and WebP; reject other formats. Accept 1..120 frames; preflight all metadata (width/height 1..4096, aggregate <=16,000,000 pixels) before explicit frame decode. Recheck decoded dimensions and aggregate, normalize retained image into 8-bit RGBA premultiplied bitmap. Return only a complete clip or throw; no partial persistence. Default missing/nonpositive/nonfinite duration 0.1s; positive timings clamp to 0.02..10s before constructing bounded CompanionClip. Explicit policy difference from arbitrary source schedules; ratios preserved after normalization, not necessarily original invalid metadata. ImageIO support for APNG/WebP and partial-compositing behavior must be tested on supported macOS; no claim of full format parity. Size ceilings bound application-owned decoded pixel storage to approximately 64 MB per clip excluding allocator overhead, transient source/decoder allocations and copies; not a hard process RSS limit. File acquisition must bound bytes before allocating Data; this API cannot bound a caller's earlier allocation. Do not invoke on the UI path for user imports without separately reviewed background decoding, cancellation/publication fence and catalog-wide budget.

## Renderer

An isolated MainActor AppKit driver consumes validated clip, scales menu image logical size to fit 18pt while preserving aspect ratio (provisional design value), emits frames to a caller-owned surface and creates no status item. Uses cursor token and per-schedule identity, one pending cancellable task. Identical clip is a no-op; rate preserves frame index; reduce motion cancels progression and freezes current frame; one-frame clip has no schedule; stop clears owned presentation once and cancels timers. Caller must wire system Reduce Motion, render ownership and restoration of existing status button, sleep/wake and configuration generation. This slice does NOT connect to production app, add a setting, subscribe Companion CPU, persist user assets or implement Desktop/Focus. No second NSStatusItem, no credential access.

An internal injected scheduler can deliberately invoke cancelled/duplicate callbacks. The new animated GIF fixture exercises normal advancement, duplicate rejection, speed changes preserving frame, Reduce Motion freeze/resume and stop with late callback. The test is independent of real-time sleeps and does not replace macOS integration or actual power measurement.

## C2b1 / C3b1: single-file intake and runtime composition

Single explicit local file selection only: reject non-file/nonlocal URLs, open with O_RDONLY/O_NOFOLLOW/O_NONBLOCK/O_CLOEXEC; fstat the opened descriptor, reject nonregular files, empty or >32 MiB; read in bounded 64 KiB chunks with cancellation checks and a one-byte growth probe. Use the same opened file for metadata and read, recheck size/mtime/ctime/device/inode at completion. This prevents final-component symlink following and path replacement redirecting later reads; it is not an immutable snapshot, a guarantee against concurrent same-size writes, or ancestor-path confinement. O_NONBLOCK prevents FIFO open blocking but cannot guarantee latency for network mounts or device opens; user-selected regular local files only, off-main caller and cancellation still required. No manifest-relative path handling, archive extraction, hidden directory scan, copy or persistence. Pack import requires separate trusted directory descriptor traversal, no-follow at every component, bounded staging and ownership checks.

A decoded catalogue requires a default state and bounds total retained pixels of unique clip revisions to 16 million; shared aliases count once. This caps successfully retained catalogue storage only; pre-decode cumulative allocation budget and replacement peak memory remain separate requirements. The single-surface runtime coordinator consumes only validated catalogue values and provides explicit enabled/visible/awake/Reduce Motion inputs, independently selected speed mode and manual state via arbitration, automatic CPU request tokens and a demand flag for the host scheduler. Disabled, hidden, asleep or missing catalogue implies no CPU demand or frame driver. Reduced motion provisionally freezes progression and suppresses CPU demand. Since automatic CPU state is cleared, the coordinator may resolve a different clip (manual state or run/default), displaying that clip's first frame without scheduling ticks; for an unchanged resolved clip the existing frame stays frozen. Explicit manual state can still change the static clip. This is a coordinator-level policy distinct from the frame driver's same-clip freeze and requires accessibility review. Catalogue is retained while hidden (bounded) and may be explicitly removed. No autonomous sampling/task loop besides renderer frame scheduling. CPU errors and session replacement clear automatic contribution, manual state remains independent. Default fallback resolves to the original clip identity without restarting. This is a composition seam, not an actual status item or user-visible setting; no production app dependency, persistence, actual sampler subscription, external event listener or Desktop/Focus integration. The host must serialize its configuration and demand transitions, call invalidateCPU on lease replacement and integrate a background single-flight asset loader with publication generation. Do not call user callbacks reentrantly into the coordinator. Add real multi-consumer app tests and real-Mac validation before activation.

## C3b2: isolated developer preview

Add a separate Tuist app target SchneeBarCompanionPreview (bundle dev.lamy.schneebar.companion-preview), not referenced by the shipping app. Launch the scheme explicitly in Xcode. Start is an explicit in-memory action; initial state has no status item, sampling or frame timer. Start generates five original geometric mascot clips (two 32x32 frames each), then owns one preview-only status item; Stop removes it, clears the catalogue and releases both demands. Do not start while the regular Bar is running; if Bar launches afterward, stop on the workspace launch notification. This is cooperative protection, not an atomic cross-process lock; do not run alongside Runner or launch duplicate preview processes for testing. No distribution or installer changes. The window provides character and raw host CPU presentation toggles, automatic/manual speed, freeze, stop and quit using the existing SchneeSurface token. No preference writes, imported files, credentials, notifications or external connections. System Reduce Motion and sleep/wake are observed. The preview model serializes short reconciliation transitions, fences in-flight result publication by revision and cancels the prior refresh loop; a single loop polls only when either consumer requests samples and both calls reuse the same actor. Five seconds after each cycle is a preview cadence, not the final scheduler contract. Do not make extra background acquisition loops in the shipping app. Closing the window stops preview. User-facing localization, reusable status-button restoration in the shipping app, asset import, app-level lifecycle and power validation remain separate. The preview is independently authored and does not authorize production adoption or source reuse. Verify all targets build/test, and run explicit manual preview checklist before claim of usable integration.

### REV-002 through REV-004

Presentation-only refresh generation changes (including CPU text visibility) do not invalidate the automatic CPU input session. Mode/active/Reduce Motion transitions still clear it through the coordinator; changed upstream epochs reseed on the next accepted observation. Cancel and fence old refresh callbacks with the host revision; preserve cached sample identity and EMA in a continuing session. Keep the last CPU text while its widget remains requested. The idle sleep must not retain the model; isolated main-actor destruction removes the optional status item, cancels refresh, drains the short demand-transition queue and revokes both consumers without retaining the model. Explicit Stop remains the normal lifecycle path. Headless preview model fixtures use an injected counter source, availability, Reduce Motion and absent presentation surface; verify toggle continuity, explicit stop, and destruction without explicit stop. Procedural frames retain one transparent border pixel at maximum offset; check alpha channel of all ten frames in the real CoreGraphics representation. macOS build/test and real-device acceptance remain required.

### REV-005/006: preview deadline and unavailable presentation

The independent preview uses the same monotonic acquisition deadline as the shipping CPU scheduler. After publishing a cached observation on a visibility change, sleep only the remaining cache interval, bounded below by 50ms; stop when the selected demand has disappeared. Revision checks surround both sampling and the deadline query. The test clock controls the 500ms bootstrap and the 4.5s cache age and intercepts sleeps, verifying a 5s then 500ms wait. If a real status surface or button cannot be created, do not activate the runtime, clear any generated catalogue and report a recoverable error; a headless surface is accepted only by explicitly opted-in test fixtures. The failure case must leave both demands absent. This is a developer-preview refinement, not production linkage or real-time response guarantee. CI and real-machine acceptance remain required.
