# E3c draft: bounded reminder collection

Based on merged #445. Add FocusReminderCollectionStore in the existing persistence target, with one application-owned actor and one distinct private snapshot file. Reuse FocusReminderState, schedule rules, and individual store commands. New entries receive internally generated UUIDs and start disabled; caller cannot choose a previously removed identifier. Imported origin remains immutable and cannot be enabled. Authorized import classification remains caller responsibility. Titles must be nonblank, at most 128 Unicode scalars / 512 UTF-8 bytes and contain no control characters. Proposed maximum 64 entries, 256 KiB encoded snapshot, canonical UUID ordering. Version 1 decoding validates nested records, title, count, unique IDs; fail closed without resetting invalid records.

Add, rename, remove and single-entry enable/replan/claim are read/modify/write transactions with no suspension. Publish claims only after successful atomic replacement. Renaming preserves schedule, cursor and ticket; removal revokes the local ticket and future commands referencing the removed UUID fail. This does not cancel a notification already submitted to the OS: future notification reconciliation must remove orphaned requests and fence delivery. Entry edits are limited to title, enable and scheduling operations; rule editing, revisions within a live entry, bulk updates, snooze, imported source deduplication and legacy migration are separate slices. Use a dedicated new file; do not open the individual reminder and collection stores for the same logical records. New UUIDs are random rather than an unbounded tombstone ledger.

Single-owner/private-directory assumptions and bounded regular-file reader remain. Atomic replacement does not imply fsync/power-loss durability or cross-process locking. Precommit write failure preserves previous bytes; uncertain commit outcomes require reload. Claims mean consumption, not OS receipt. No new external dependencies, timers, shipping UI or notification effects. Existing imported-data-only and release gates remain.

Five new tests cover independent claims, cross-entry ticket rejection, delete/recreate and stale commands; imported activation and harmless rename/title validation; concurrent 70 additions enforcing 64 entries; failed writes on claim/remove; duplicate/future/over-capacity record rejection with byte preservation. Linux Swift 6.2.1 isolated SwiftPM harness ran 16/16 including 11 prior reminder tests; local bounded POSIX reader stand-in is not the exact Darwin production implementation. Mutation replacing removal with a no-op failed the selected regression with two issues (stale claim and unexpected count); restoration passed all 16. Both new source/test blobs match local verification. Native CI required before merge. Tasks 4.2/4.3/7.3/7.5/9.6 remain partial; real-device, rights, ADR and main promotion unchanged.
