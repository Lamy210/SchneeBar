# E1a draft: native deadline-authoritative countdown domain

Based on merged #436/#437. Independently implement a new native FocusCore from the existing productivity requirements; no SchneeRunner source or artwork copied. The Tuist module has no dependencies beyond Foundation, and the shipping app does not depend on it.

One countdown has a stable UUID, original duration and running/paused/completed/cancelled state. Running state stores an absolute Date deadline, not a remaining tick count. Display reads clamp to zero and the original duration without mutating the record. Explicit reconcile at/after the deadline transitions once to completed and returns the stable countdown ID and original deadline; a late pause/cancel reconciles expiry first. Pausing preserves remaining time and explicit resume creates the next deadline from that remainder. Completed and cancelled items never resume. Version 1 Codable validates duration, finite bounded dates, paused remainder and schema version on decode. Proposed duration bound: greater than zero and at most 24 hours; not a claim of Runner compatibility.

Sleep/restart with a normally advancing wall clock cannot extend a running deadline, including restoration of a previously completed record. A manual backward wall-clock change may delay expiration of a running deadline; display is bounded by original duration. Define a separate monotonic/clock-change policy before production. Do not claim exactly-once external notification: the future store must commit the completed record before dispatch, reconcile stable identifiers, and handle crash between commit and dispatch. No timer task, notification API, storage IO, legacy decoding, migration activation, Pomodoro sequencing, or production UI here. Imported notification-bearing items remain inactive per productivity spec.

Eight focused tests cover restart/sleep, once-only terminal transition, pause/resume, late commands, cancellation, invalid record/clock/duration/schema, rollback display clamp, maximum duration and exact deadline, and failed-resume state preservation. The Swift Testing require macro receives the already reconciled value rather than invoking a mutating method on an immutable macro receiver. Local Linux Swift 6.2.1 verification reproduced the original compiler error and passed all eight corrected tests; deliberately changing the deadline comparison from inclusive to exclusive failed the exact-deadline test, and restoring the implementation passed all eight again. This does not replace native Tuist/Xcode 26.6 CI. Native CI must demonstrate execution of the new test target; real-device clock behavior, durable transactions, Pomodoro, notification, recurrence, and UI follow separately. Tasks 4.1/9.6 are only partially addressed and remain unchecked. ADR-0004 and rights/main promotion gates remain unchanged.
