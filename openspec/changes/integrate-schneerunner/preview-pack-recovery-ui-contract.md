# C3b draft: preview library recovery controls

Stack on #406 without modifying its CI. Inventory distinguishes a safe fixed pending selection file from unknown entries; both block installation. Unsafe pending records remain unknown and cannot be discarded via this UI. Explicit actions by UUID only, existing root locks/descriptor checks unchanged. Confirm full identity and action; confirmations carry preview visibility session, recheck membership and worker availability immediately before submission. No action on stale session or absent target. User owns only the copied preview pack, never the source. If currently displaying the target of trash, switch to independently generated built-in before durable worker starts; on failure retain built-in and request explicit saved-choice restore. Store clears persistent selection before rename, restore never selects. Other actions preserve current display. No automatic deletion or unknown-name/path input. Recovery controls share one worker, no additional decode loop or file traversal outside store. Disable explicit Quit during worker; closing/OS termination remains outside guarantee. Bounded scroll region, names/UUIDs, explicit destructive confirmation, generic errors. Three native regression tests (pending record classification, preview trash/restore/purge/stale session, explicit stage/pending recovery preserving unrelated data). Native CI, real UI/accessibility, disk-full/partial deletion/power-loss and ADR gates remain. No shipping linkage or release.
