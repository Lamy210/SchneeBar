# C3q draft: read-only saved selection validation

Based on merged #419; independent of #420–#422. Separate read-only observation from the existing mutating explicit recovery. Read the committed selection record and decode the selected pack while holding one shared root lock. Missing record means built-in; a valid selected ID whose catalogue is unavailable returns unavailable with that ID without deleting or rewriting the record. Malformed/unsafe selection records and root/lock errors propagate rather than silently choosing built-in. Cancellation propagates; all paths release the root descriptor. Existing restoreSelection remains explicit and may clear an invalid saved choice.

Two fixtures exercise installed/missing/corrupt catalogue, byte preservation, explicit recovery distinction, malformed/symlink record and lock contention. A later host worker must use the existing single bounded queue and publication ticket to consume this API and decide whether to admit approved built-in artwork. No automatic repair, asset writes, source migration, shipping target dependency or release approval. On-disk fixtures in CI are not a substitute for the real-Mac and rights gates.
